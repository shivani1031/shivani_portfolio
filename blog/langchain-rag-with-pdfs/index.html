LangChain RAG with PDFs: load, split and query

To build LangChain RAG over PDFs, load each PDF one page at a time so that every Document carries its page number, strip running headers and page numbers, set aside pages with no text layer for OCR, then split the pages with RecursiveCharacterTextSplitter and store them. The page number then follows each chunk into the index, so you can filter by file at search time and cite a file and page in every answer.

What this guide adds

The LangChain RAG tutorial builds a minimal pipeline over Markdown files, with a retrieval check and two ways to answer. RAG for PDFs and tables covers the parsing decisions for difficult documents: choosing parsers, handling tables, scans and charts. This guide sits between them. It takes the tutorial's pipeline and swaps in PDFs with a text layer, the kind exported from a word processor, and deals with the problems they bring: page numbers, repeated headers, empty pages and citations. If your PDFs are scanned or table-heavy, read the parsing guide first.

Step 1: choose how to load the PDF

Many LangChain PDF tutorials use PyPDFLoader. Check the current LangChain document loader page before you follow them. At the time of writing, it says that PyPDFLoader, PyMuPDFLoader, PDFMinerLoader and PDFPlumberLoader live in the unmaintained langchain-community package and should no longer be used, and it recommends partner packages such as Docling, Unstructured or Upstage for new work.

That leaves two reasonable options:

  • A partner loader, such as DoclingLoader from the langchain-docling package. These are layout-aware and suit documents with headings, columns or tables, at the cost of more dependencies and compute.
  • A small loader of your own on top of a PDF library such as pypdf. For clean, text-based PDFs this is short, has one dependency and gives you full control over metadata.

Every LangChain loader implements the BaseLoader interface, so whichever you pick, the rest of the pipeline stays the same. Here is the second option:

# Illustrative: one Document per PDF page, with page numbers in metadata.
import re
from collections import Counter
from pathlib import Path

from langchain_core.document_loaders import BaseLoader
from langchain_core.documents import Document
from pypdf import PdfReader


class PdfPageLoader(BaseLoader):
    def __init__(self, path):
        self.path = Path(path)

    def lazy_load(self):
        reader = PdfReader(self.path)
        for number, page in enumerate(reader.pages, start=1):
            text = page.extract_text() or ""
            yield Document(
                page_content=text,
                metadata={
                    "source": self.path.name,
                    "page": number,
                    "has_text": bool(text.strip()),
                },
            )

Illustrative sketch, run against pypdf 7.0.1 and langchain-core 1.8.0 on a generated test PDF.

Implementing lazy_load is enough: BaseLoader provides load on top of it, and yielding one page at a time keeps memory flat on large files. Page numbers start at 1 here because that is what people see in a PDF viewer. Some loaders count from 0, so check before you show page numbers to users. If a document uses printed labels such as roman numerals for the front matter, pypdf can read the labels too, which you may prefer for citations.

Step 2: flag pages with no text

A page that returns no text is usually a scanned image, a page that is only a figure, or a blank separator. The loader records this as has_text instead of silently dropping the page. That matters because an index with missing pages fails quietly: questions about those pages return the nearest other chunks, and the model may answer from the wrong place.

Keep a list of these pages per file. A handful of blank pages is normal. Many pages without text in one file means it is a scan, and it needs OCR, covered in the parsing guide, before it belongs in the index.

Step 3: strip headers, footers and page numbers

Text extracted from PDFs includes everything on the page, including a running header such as the document title and a footer such as "Page 3 of 40". Left in place, these lines repeat across chunks, make unrelated chunks look similar to each other and waste context. A simple and effective fix is to drop lines that appear on most pages, plus lines that are only a page number:

# Illustrative: drops running headers, footers and page numbers.
PAGE_NUMBER = re.compile(r"^(page\s+)?\d+(\s+of\s+\d+)?$", re.IGNORECASE)


def strip_repeated_lines(pages, threshold=0.6):
    counts = Counter()
    for doc in pages:
        counts.update({line.strip() for line in doc.page_content.splitlines() if line.strip()})
    limit = max(2, int(len(pages) * threshold))
    repeated = {line for line, n in counts.items() if n >= limit}
    for doc in pages:
        kept = [
            line for line in doc.page_content.splitlines()
            if line.strip() not in repeated and not PAGE_NUMBER.match(line.strip())
        ]
        doc.page_content = "\n".join(kept)
    return pages

Illustrative sketch. The threshold is an example; check the removed lines on your own documents.

Check what this removes on a sample of your files before you trust it. A short line such as "Notes" can legitimately repeat, and a document with very few pages gives the counts little to work with, which is why the minimum is two. Headers that include a chapter name change every few pages and may slip through; if they matter, record them as metadata instead of discarding them.

Step 4: split pages and keep the page number

Splitting works on the cleaned pages, not on whole files. Because split_documents copies each Document's metadata to every chunk it makes, the source file and page number reach the index without extra code:

# Illustrative: index pages with text, search, and cite file and page.
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_text_splitters import RecursiveCharacterTextSplitter


def index_pdfs(paths, embeddings):
    pages, needs_ocr = [], []
    for path in paths:
        loaded = list(PdfPageLoader(path).lazy_load())
        needs_ocr += [(d.metadata["source"], d.metadata["page"]) for d in loaded if not d.metadata["has_text"]]
        pages += strip_repeated_lines([d for d in loaded if d.metadata["has_text"]])
    splitter = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100, add_start_index=True)
    store = InMemoryVectorStore(embedding=embeddings)
    store.add_documents(splitter.split_documents(pages))
    return store, needs_ocr


def search_pdfs(store, question, source=None, k=4):
    only = (lambda doc: doc.metadata["source"] == source) if source else None
    docs = store.similarity_search(question, k=k, filter=only)
    return [(f"{d.metadata['source']} p.{d.metadata['page']}", d.page_content) for d in docs]

Illustrative sketch, run with LangChain's DeterministicFakeEmbedding in place of a real embedding model. The chunk sizes count characters and are examples, not recommendations.

Splitting by page has one cost: a sentence that runs from the bottom of one page onto the next is cut in two. For most documents this affects few answers. If testing shows it matters, join each page with the first few lines of the next before splitting, and keep the starting page as the citation. If your documents have clear sections, a structure-aware loader that splits by heading will usually do better than either. RAG chunk size and overlap covers how to choose the numbers.

Step 5: query with filters and page citations

search_pdfs returns a citation such as handbook.pdf p.12 alongside each passage. Pass those labels into the prompt with the passages and ask the model to cite them, as in the tutorial's two-step answer function. A citation with a page number is far more useful to a reader than a file name alone, because they can open the PDF and check the passage in seconds.

The source argument narrows the search to one file. InMemoryVectorStore takes a function that receives each Document and returns whether to keep it. Persistent vector stores use their own filter syntax, usually a dictionary of metadata conditions, so this line is the one to rewrite when you move off the in-memory store. Filters matter more with PDFs than with short web pages, because a collection often holds several versions of the same handbook or contract, and a question about this year's version should not be answered from last year's.

Store the document version or date in metadata at load time for exactly that reason. It is much harder to add later, once chunks from several versions are already mixed in the index.

Step 6: test the PDF-specific failures

The retrieval check from the tutorial still applies: a set of questions with the file that should answer each one. For PDFs, extend it in three ways:

  • Expect a page, not just a file. Record the page that answers each question and check that it appears in the results. A long PDF in which the right file comes back from the wrong page is still a failure.
  • Include questions near page breaks. These show whether splitting by page is costing you answers.
  • Check the OCR list. Fail the ingestion run, or at least warn, when a file has more pages without text than you expect.

Read the extracted text of a few pages from each document type, too. Text-layer PDFs can still extract badly: words run together, columns interleave, ligatures turn into odd characters. No amount of retrieval tuning fixes text that was wrong when it went in.

Common mistakes with PDFs in LangChain

  • Loading a whole file as one Document. The page number is lost before splitting, and citations can only name the file.
  • Copying a loader from an old tutorial. Check its package against the current loader page first.
  • Dropping empty pages silently. Record them so that scans are noticed.
  • Leaving headers in. They make chunks look alike and push useful text out of the context.
  • Ignoring versions. Without a version in metadata, old and new documents compete in the same results.

Frequently asked questions

Is PyPDFLoader still recommended in LangChain?

Not for new work, according to the current LangChain document loader page. It lists PyPDFLoader among classes in the unmaintained langchain-community package and recommends partner packages such as Docling or Unstructured, or you can write a small loader of your own.

How do I keep page numbers in LangChain RAG?

Create one Document per page with the page number in its metadata. The text splitter copies metadata to every chunk it creates, so each search result can be cited with its file and page.

Why does my PDF chatbot miss some pages?

Often the pages have no text layer, because they are scans or images. Text extraction returns nothing for them, so they never reach the index. Record such pages at load time and send them for OCR.

Should I split PDFs by page or by section?

Page splitting is simple and gives exact citations, but it cuts sentences at page breaks. Section splitting keeps ideas together and suits structured documents. Test both on questions that fall near page boundaries.
