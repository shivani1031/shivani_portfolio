Building a local RAG chatbot in Python with Ollama

A local RAG chatbot lets a language model answer from your private documents instead of only its training data, without sending anything to an external API. In Python, you run two phases. Indexing splits documents into overlapping chunks and embeds them with a local embedding model served by Ollama. Answering embeds each question, retrieves the closest chunks and asks a local chat model, also through Ollama, to answer only from them and cite its sources.

Why run RAG locally

Retrieval-augmented generation, or RAG, gives a model the relevant passages from your own content at the moment it answers. Most tutorials send both the passages and the question to a hosted model. That is often fine, but some documents should not leave your network: contracts, HR files, medical notes, unreleased product plans or anything covered by a client agreement. Running the models yourself removes that question, because the text never leaves the machine.

Ollama is a tool for downloading and running open-weight language models on your own computer or server. It exposes a local HTTP interface, and its official Python package, ollama, wraps that interface in simple functions. That makes it a convenient way to prototype a private RAG chatbot in Python.

Local is not automatically better. Smaller local models usually reason less reliably than the largest hosted ones, answers can be slower on ordinary hardware, and you take on updates and monitoring yourself. Treat it as a trade-off to test on your own questions, not a default. If the general pattern is new to you, how to build a RAG chatbot in Python walks through it with provider-neutral placeholders, and this guide fills those placeholders with local models.

What you need

  • Ollama installed and running. Follow the installer for your operating system from the official Ollama site, then check that the local service is up.
  • Two models pulled. One chat model and one embedding model. The names in the code below, llama3.2 and nomic-embed-text, are examples only. Check the Ollama model library for what is currently available and suits your hardware, and pull each with ollama pull <name>.
  • The Python client. Install it with pip install ollama. Its chat and embed functions are the only calls used here.
  • A small folder of clean text. Start with Markdown or plain text so that parsing problems do not hide retrieval problems.

Hardware matters more locally than with an API. A machine with a supported GPU, or plenty of memory on Apple silicon, will run larger models at a usable speed. On a modest laptop, start with a small model and judge quality before scaling up.

The two phases: indexing and answering

Every RAG system has the same two halves. Indexing runs ahead of time: load documents, split them into chunks, turn each chunk into a vector with an embedding model and store the vectors alongside the text. Answering runs for every question: embed the question with the same embedding model, find the chunks whose vectors are closest, put them into a prompt and ask the chat model to answer from them.

Keeping these as separate functions pays off later. Indexing can move into a scheduled job when documents change, and the answering code does not need to know.

A minimal local RAG chatbot

The sample below is illustrative teaching code, not production software. It uses the official ollama Python package and keeps the index in a plain Python list, so that every step is visible:

# Illustrative only. Assumes Ollama is running locally and both models are pulled.
import math
import ollama

CHAT_MODEL = "llama3.2"         # any chat model you have pulled
EMBED_MODEL = "nomic-embed-text"  # any embedding model you have pulled

def split(text, size=800, overlap=150):
    """Split text into overlapping character chunks."""
    step = size - overlap
    return [text[i:i + size] for i in range(0, max(len(text) - overlap, 1), step)]

def embed(texts):
    return ollama.embed(model=EMBED_MODEL, input=texts)["embeddings"]

def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))

# Phase 1: indexing
def build_index(docs):
    index = []
    for name, text in docs.items():
        chunks = split(text)
        for chunk, vector in zip(chunks, embed(chunks)):
            index.append({"source": name, "text": chunk, "vector": vector})
    return index

# Phase 2: answering
SYSTEM = (
    "Answer only from the numbered passages. Cite them like [1]. "
    "If they do not contain the answer, say you do not know."
)

def answer(question, index, k=3, min_score=0.3):
    q = embed([question])[0]
    scored = sorted(((cosine(q, c["vector"]), c) for c in index), key=lambda p: p[0], reverse=True)
    hits = [c for score, c in scored[:k] if score >= min_score]
    if not hits:
        return "I could not find that in the documents."
    context = "\n\n".join(f"[{i}] ({c['source']}) {c['text']}" for i, c in enumerate(hits, 1))
    response = ollama.chat(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM},
            {"role": "user", "content": f"Passages:\n{context}\n\nQuestion: {question}"},
        ],
        options={"temperature": 0},
    )
    return response["message"]["content"]

if __name__ == "__main__":
    docs = {"returns.md": "Items can be returned within 30 days with a receipt. Refunds go to the original payment method."}
    index = build_index(docs)
    print(answer("How long do I have to return something?", index))

A few details are worth noticing.

  • Overlapping chunks. Each chunk shares some characters with the one before it, so that a sentence cut at a boundary still appears whole in at least one chunk. The sizes here are starting points to tune, as choosing chunk size and overlap explains.
  • One embedding model for both phases. Questions and chunks must be embedded by the same model, or the similarity scores mean nothing. If you change the embedding model, rebuild the index.
  • A minimum score. If nothing is close enough, the function declines rather than letting the model guess from its training data. The right threshold depends on the embedding model, so tune it on your questions.
  • Temperature zero. The options argument passes generation settings to Ollama. A low temperature makes answers steadier, which helps when you are testing.

The response from ollama.chat holds the reply text under message and then content, and ollama.embed returns one vector per input under embeddings. These shapes come from the client's own documentation; check them against the version you install, as client libraries do change.

Using LangChain instead

If the rest of your project already uses LangChain, its Ollama integration lives in the langchain-ollama package, which provides ChatOllama for chat and OllamaEmbeddings for embeddings. You can drop these into the pipeline from the LangChain RAG tutorial in place of a hosted model. This illustrative snippet shows the two classes on their own:

# Illustrative only. The same two models through LangChain's Ollama integration.
from langchain_ollama import ChatOllama, OllamaEmbeddings

llm = ChatOllama(model="llama3.2", temperature=0)
embeddings = OllamaEmbeddings(model="nomic-embed-text")

vectors = embeddings.embed_documents(["Items can be returned within 30 days."])
reply = llm.invoke([("system", "Answer only from the passages."), ("human", "Passages: ...\n\nQuestion: ...")])
print(reply.content)

LangChain adds document loaders, text splitters and vector store integrations, which saves time once the pipeline grows. It also adds a layer to debug. For a first local prototype, the plain client keeps things easier to inspect.

Storing the index properly

A Python list is fine for a few hundred chunks and disappears when the program stops. For anything larger, store the vectors in a vector database that persists to disk. ChromaDB is a common choice for local projects because it can run inside your Python process and save to a folder; the ChromaDB RAG tutorial shows indexing, persistence and metadata filters. You can pass the vectors from ollama.embed straight into it.

Store the source file name, a section heading and a date with each chunk. They make citations meaningful, and they let you filter or delete by document later.

Testing before you trust it

Write down a couple of dozen real questions with the answers an expert would give and where each answer lives, and include some your documents cannot answer. Run them after every change of model, chunk size or prompt. Check two things separately: whether the right passages were retrieved, and whether the answer used them faithfully. How to evaluate a RAG system covers this in more depth.

Local models vary a great deal, so compare two or three on the same questions rather than choosing by reputation. A slightly larger model that follows the "answer only from the passages" instruction reliably is usually worth more than a faster one that does not.

Taking it further

  • Conversation memory. Rewrite follow-up questions as standalone ones before retrieval, as described in RAG chatbots with conversation memory.
  • Serving. Wrap the answering function in a small web API so that a browser front end can call it, and keep the Ollama service itself reachable only from the machines that need it.
  • Privacy beyond the model. Local models protect the prompt, but logs, backups and the index itself still contain your documents. Protect them as you would the originals.

Frequently asked questions

Can I build a RAG chatbot that runs completely offline?

Yes. Once Ollama and the models are downloaded, indexing and answering can run without an internet connection, because the embedding model, the chat model and the index all live on your own machine.

What is the Ollama Python package called?

The official package is named ollama and is installed with pip install ollama. It provides functions such as chat and embed that call a locally running Ollama service.

Do I need LangChain to use Ollama for RAG?

No. The ollama package alone is enough for a working prototype. LangChain's langchain-ollama package, with ChatOllama and OllamaEmbeddings, is useful if your project already uses LangChain loaders, splitters or vector stores.

Which local model should I use for RAG?

There is no single answer. Pull two or three chat models that fit your hardware, run the same set of real questions through each, and keep the one that answers accurately from the passages and declines when they do not contain the answer.

Is a local RAG chatbot more private than a hosted one?

It keeps your documents and questions away from external model providers, which removes one major risk. You still need to protect the index, logs and backups, and control who can use the chatbot.
